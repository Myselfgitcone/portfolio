Footnote AI engineering Live · refreshed every morning

Ask about twenty public companies' annual reports and get an answer where every claim cites its passage and every figure is the number filed with the SEC.

Situation

Financial questions are a common use for LLMs, but models invent numbers and misread tables, and a single 10-K runs hundreds of pages, so answers are hard to trust or check.

Task

Build a production-style RAG system over SEC filings where every claim carries a citation, every number is the officially filed figure, and answer quality is measured automatically.

Action

  • A daily serverless pipeline on AWS pulls 10-Ks from SEC EDGAR into S3 and splits them into sections, all provisioned with Terraform.
  • Sections are cut into overlapping passages and embedded on CPU with bge-small, avoiding about 10 million tokens of hosted embeddings, then indexed in Pinecone with their source.
  • A LangGraph pipeline: Claude plans the question, text search and an exact-figure lookup from XBRL run in parallel, then Claude writes an answer that may cite only what was retrieved.
  • A 29-question evaluation suite in LangSmith with a stronger model as judge, run as a CI gate that blocks any change that lowers answer quality.
  • Found and fixed a real data problem: Exxon's ticker moved to a new holding company in 2026 and its filings silently vanished. Ingest now follows predecessor registrants and flags any company that comes back empty.

Result

  • 106 annual reports, 20 companies, about 27,000 passages, refreshed every morning.
  • 100% of figure questions answered with the exact filed number, such as Apple's fiscal 2024 revenue of $391,035 million.
  • Grounding went from 87% to 100% after the first eval run caught cut-off answers and an invented quote.
  • Runs inside the AWS free tier with a $1 a month budget alarm, at about $0.002 a question.

Situation

Market, weather and crop data arrive from different public sources at different speeds and in different shapes, so answering "when US corn ratings fall, does corn rise the next week?" needs a trustworthy pipeline first.

Task

Build a streaming lakehouse where one set of data contracts governs every dataset from producer to gold table, then use it to answer the question with statistical evidence.

Action

  • One YAML contract per dataset drives validation, schemas, tests and freshness alerts; invalid records go to a dead-letter queue or quarantine table, never the lake.
  • Kafka and Spark Structured Streaming land data in Apache Iceberg; dbt on Trino models silver and gold, orchestrated by Dagster with freshness checks and nightly compaction.
  • Fixed a Spark out-of-memory failure on a ten-year backfill by switching Iceberg to clustered writes.
  • Caught a modeling bug: averaging 41 states diluted the signal, so the mart now uses USDA's official 18 states.
  • The same dbt models run on DuckDB to publish a free public dashboard four times a day.

Result

  • Corn rose 0.93% the week after ratings fell and fell 0.79% after they rose, significant over 257 weeks (p ≈ 0.01).
  • 9,049 daily price bars and 68,730 crop-condition rows loaded, with no row failing its contract.
  • 44 unit tests and 60 dbt nodes run in CI on every change.
  • Runs for free, refreshed four times a day.

Silo AI engineering · MCP Live · answers from Grainflow's latest build

Ask Grainflow's data a question in plain English and get the numbers with the SQL behind them, through an MCP server any AI client can use.

Situation

Letting an LLM write SQL against real data is risky: it can run unsafe queries, average the wrong columns, or return a confident wrong number.

Task

Let any AI agent answer questions about the Grainflow lakehouse safely, accurately and cheaply, and prove it with tests.

Action

  • An MCP server with six tools and a semantic metrics layer that encodes analyst rules, such as never averaging corn with soybeans.
  • Two locks on free-form SQL: a sqlglot parser that allows exactly one read-only SELECT, and a database engine configured so it cannot touch files or the network even if a query slips through.
  • An agent with a daily budget, a step cap and prompt caching, showing every tool call, query, cost and latency to the user.
  • Evals whose expected answers are computed by SQL at test time, so they stay correct as the data refreshes, run as a CI gate.

Result

  • 13 graded questions gate every change; the first run caught a wrong ranking, fixed by letting the database rank instead of the model.
  • About $0.001 an answer, with a daily budget and per-visitor limits.
  • Read-only by design: unsafe queries are rejected with a reason the agent can act on.

Situation

CDC pipelines lose or duplicate changes when a sync fails, and late-delivery models are often trained on mislabeled data, with in-transit orders counted as on time.

Task

Capture every insert, update and delete from a live order database into Databricks without losing or misordering a change, and build a late-delivery model that can be checked against known ground truth.

Action

  • Changes stream from a Postgres replication slot through Debezium; the slot only advances after a batch has landed in Databricks, so a failed sync loses nothing.
  • A Lakeflow bronze, silver and gold pipeline applies changes in log order with SCD Type 1 and 2, and joins each order to the customer as they were at checkout.
  • A gradient-boosted model with censoring-aware labels: orders not yet due are unknown, not on time, with a time-based train/test split.
  • Known causes of lateness were planted in the source data, so the model is graded on finding the real causes, not just on a score. MLflow promotes a challenger only when it beats the champion.
  • CI replays every captured event and checks it rebuilds the source tables row for row.

Result

  • Model AUC 0.90, against 0.67 from carrier late rates alone.
  • All four planted causes of lateness identified.
  • Zero lost changes: replayed duplicates are removed by log position, proven by row-for-row replay checks in CI.
  • Syncs every six hours, with a live page showing predictions and the model's track record.
